---
title: "POST /api/v1/partner/v1/customers — Register Customer"
sidebarTitle: "Register Customer"
description: "Register a new customer under your partner account. Returns a customerId used in all subsequent calls for this customer."
---

Before any customer can hold a balance or transact on Dutchman Bridge, they must be registered under your partner account. This endpoint creates the customer record and returns a `customerId` — a stable identifier you store on your side and pass to every subsequent customer-scoped call. Email addresses are scoped to your partner account, so the same email can exist under different partners.

## Endpoint

```
POST https://app.dutchmannetwork.online/api/v1/partner/v1/customers
```

## Authentication

All requests must include your partner API key as a header:

```
x-api-key: YOUR_API_KEY
```

## Request Body

<ParamField body="email" type="string" required>
  Customer's email address. Must be unique within your partner account.
</ParamField>

<ParamField body="firstName" type="string" required>
  Customer's first name.
</ParamField>

<ParamField body="lastName" type="string" required>
  Customer's last name.
</ParamField>

<ParamField body="phone" type="string" required>
  Phone number in E.164 format (e.g., `+2348012345678`).
</ParamField>

<ParamField body="country" type="string" required>
  ISO 3166-1 alpha-2 country code (e.g., `NG`). Use the [`GET /countries`](/api-reference/partner/countries) endpoint to retrieve the list of currently enabled countries.
</ParamField>

<ParamField body="password" type="string">
  Optional initial password for the customer's account.
</ParamField>

## Response

All responses follow the `{ success, data }` envelope. On success, `data` contains the newly created customer object.

<ResponseField name="id" type="string">
  Unique customer ID (`customerId`) used in all subsequent customer-scoped API calls.
</ResponseField>

<ResponseField name="email" type="string">
  The email address supplied at registration.
</ResponseField>

<ResponseField name="firstName" type="string">
  Customer's first name.
</ResponseField>

<ResponseField name="lastName" type="string">
  Customer's last name.
</ResponseField>

<ResponseField name="phone" type="string">
  Customer's phone number in E.164 format.
</ResponseField>

<ResponseField name="country" type="string">
  ISO 3166-1 alpha-2 country code for the customer's country.
</ResponseField>

<ResponseField name="status" type="string">
  Account status. One of `active` or `suspended`.
</ResponseField>

<ResponseField name="kycStatus" type="string">
  Overall KYC status reflecting the customer's highest completed verification tier.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp of when the customer account was created.
</ResponseField>

## Example

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://app.dutchmannetwork.online/api/v1/partner/v1/customers \
  --header 'x-api-key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "email": "amaka.obi@example.com",
    "firstName": "Amaka",
    "lastName": "Obi",
    "phone": "+2348012345678",
    "country": "NG",
    "password": "S3cur3P@ss!"
  }'
```

```json Request Body
{
  "email": "amaka.obi@example.com",
  "firstName": "Amaka",
  "lastName": "Obi",
  "phone": "+2348012345678",
  "country": "NG",
  "password": "S3cur3P@ss!"
}
```

```json Response (201)
{
  "success": true,
  "data": {
    "id": "cust_01HXYZ1234ABCDEF",
    "email": "amaka.obi@example.com",
    "firstName": "Amaka",
    "lastName": "Obi",
    "phone": "+2348012345678",
    "country": "NG",
    "status": "active",
    "kycStatus": "none",
    "createdAt": "2024-06-15T09:23:11.000Z"
  }
}
```

</CodeGroup>

<Note>
  A `409 Conflict` is returned if a customer with that email address already exists under your partner account. If you need to retrieve an existing customer, use [`GET /customers/{customerId}`](/api-reference/customers/get) instead.
</Note>
